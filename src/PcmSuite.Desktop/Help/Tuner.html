The Tuner

The Tuner edits the calibration inside a BIN file, using an XDF definition that says where each table is and how to scale it. It never talks to the PCM: it works on files. Reading and writing are done on the Flash tab.

Projects

A project is one folder per vehicle, inside Documents\PcmSuite Projects:

  • project.json - the name, vehicle details, the XDF and BIN last used, and which BIN is the base.
  • reads - BINs read from the PCM. The first one is the untouched base; never edit it.
  • edits - the tunes you save from the Tuner (Name_v1.bin, Name_v2.bin ...).
  • logs - Logger recordings. While a project is open, the Logger records here.
  • changes.log - every edit, with time, BIN, table and old and new values.
  • notes.json - your notes, kept by BIN file name so the folder can be copied to another computer.

Open the menu (the ☰ button), then Project, then Projects... to see your projects, open one, or make a new one. A new project asks how the tune starts: read it from the PCM (you are taken to the Flash tab), start from a BIN you already have (it is copied into reads as the base), or decide later.

Opening a project opens its BIN: the one used last, otherwise the newest file in edits, otherwise the newest in reads. The next time PcmSuite starts, it reopens the project that was open. Open a project folder... can turn a folder you made yourself into a project (its files stay where they are). The Open BIN button reads Add BIN... inside a project: a file from elsewhere is copied into reads.

A folder is a project when it contains a project.json. The smallest one is { "Name": "My Impala" }.

Opening a BIN and its XDF

Open a BIN and the Tuner looks for its XDF by the part numbers (OS IDs) inside the BIN: it wants an XDF with that number in its file name, in the BIN's folder, the project folder or the shared XDF library (Documents\PcmSuite Projects\XDFs). The top bar shows which XDF was found. If none is found, the status bar lists the part numbers and where it looked. Open XDF... (in the menu) picks one yourself, and Auto-detect XDF goes back to the automatic choice. A readable XDF you choose is copied into the library.

Protected XDFs. Some XDFs (often named Operating System ... .xdf or OS... .xdf) are protected by their author and are not XML. Only TunerPro can open them; PcmSuite cannot. The Tuner says so, keeps whatever XDF was open, and when it auto-detects it skips unreadable XDFs and takes the next match. Use an unprotected XDF for the same operating system.

Your own definition. With a BIN and its XDF open, Save as my definition (in the menu) writes the tables on screen to the XDF library as a plain XDF named <OS ID> - my definition.xdf. Because its name carries the OS ID, any other BIN with that OS finds it automatically, and TunerPro opens it too. An earlier definition is never replaced (a new one is numbered "(2)"). Patches are not included. When a BIN has both your definition and the XDF it came from, yours is used.

Editing and adding tables. Right-click a table in the list and choose Edit definition... to change where its values are, their size, scaling, units and headings, or use New table... (in the menu) for one the XDF does not have. A preview shows the numbers the definition gives for the open BIN, so a wrong address or size shows up straight away; mistakes are listed and Apply waits until they are fixed. Headings can be unknown, typed, or read from the BIN, so they follow the file. Applying changes this session's definition only: the XDF you opened and the BIN are not touched. Use Save as my definition to keep the result.

A BIN with no XDF. If you have an XDF for a similar operating system, Find tables from a similar BIN... (in the menu) uses it. The page first suggests the best references among your own BINs (the Reference BINs folder and every project): BINs of the same size that have an XDF the Tuner can read, with the closest first, each already compared with this one and its folder shown. You can also pick a BIN yourself. The Tuner compares the two BINs and works out where each table went. A truck calibration is a better reference for a truck, and the more of your own BINs it has to choose from, the better the suggestion. Between versions of the same family the calibration moves by small amounts, so most tables can be located: some by their own values (●), some because the tables around them moved by the same amount (◐), and some cannot be placed (○). You see the list before anything is added. These placements are the Tuner's best guess, not an XDF author's work: open a few tables, check that the numbers look believable, and use the Definition... button on any that are off. Nothing in either BIN or in the XDF is changed, and Save as my definition keeps the result for next time.

The screen

  • Top bar - the menu, Open BIN / Add BIN, Save As, the open BIN and XDF, the project name, and a MODIFIED mark when there are unsaved edits.
  • Parameter list (left) - every table and value in the XDF, grouped as the XDF groups them. Type in the search box to filter; the tag drop-down filters by tag. Hide list gives a big table the whole width. Pinned tables appear in a folder at the top.
  • Editor (right) - the open table, with its toolbar.
  • Notes and description - folds open under the editor: your note for the table, and the XDF's description of it.
  • On a narrow window (or a phone) the three areas become pages with buttons at the bottom.

The menu has sections for Project, Files (Open Reference BINs folder, Open XDF, Auto-detect, recent BINs), Tools (Swap segments, Logging profiles, VE wizard, Log map, Compare workbench, Hex view), Records (Open change log, Export notes) and Checks (Check checksums, Compare with: a matching BIN, Compare with BIN).

Editing a table

The grid works like a spreadsheet. Cells are coloured from blue (lowest) to red (highest). The axis values are frozen so you can always see which row and column you are in.

Selecting

  • Click a cell to select it; drag across cells, or Shift+click, to select a block.
  • Click a column heading or row heading to select the whole column or row. Ctrl+A selects everything.
  • The arrow keys move the selection; Shift+arrows grow it. A line above the grid shows the selection's size, minimum, maximum and average.

Typing a value

  • Start typing a digit, or press Enter or F2, or double-click, to edit the selected cell. Enter stores the value and moves down; Esc cancels.
  • Shift+Enter puts the typed value into every selected cell.
  • The BIN can only hold certain values (it stores whole numbers that are scaled). A typed value is rounded to the nearest one the BIN can hold, so you may see 1.0 become 0.9998. That is the table's resolution, not a mistake.

Block tools

  • + and - nudge the selection by the smallest step the BIN can hold (hold Shift for ten steps).
  • Scale × multiplies the selected cells by a factor (1.05 is +5%). With a single cell selected it scales the whole table.
  • Interpolate (Ctrl+I) fills a selected block by blending between its four corners; the corners stay as they are.
  • Smooth averages each selected cell with its neighbours inside the block; the corners stay fixed.
  • Copy copies the whole table with its axes for a spreadsheet; Ctrl+C copies the selection and Ctrl+V pastes numbers copied from a spreadsheet (one pasted value fills the whole selection).

Single values (one-cell tables) are edited by clicking them. A table that is a set of on/off flags shows a check box. 3D view shows a table as a surface.

Trouble code tables. Where a table's rows are standard trouble codes (such as P0101 or P0420), a short description of each code is shown beside its row. Only the standard codes are described. GM-specific P1xxx codes mean different things on different vehicles, so they are left without a description. The search box above the table list also finds trouble codes: type P0420 or a word from the description such as catalyst and the list shows the tables that have that code. In an open code table the matching rows turn amber and the first one is scrolled into view. To switch many codes at once, select the cells and use Shift+Enter after typing a value, or the fill commands.

Undo, redo and history

Undo and Redo (Ctrl+Z, Ctrl+Y, or the buttons beside the table name) step through your edits to the table, and each block tool counts as one step. History lists recent edits: pick one to take back everything after it. Each open table keeps its own history. Nothing reaches the file until you save, so closing without saving also throws the edits away.

Several tables open

Pick a table in the list and it opens in a tab above the grid; picking it again switches to its tab. Close a tab with its ✕ or Ctrl+W. Closing a tab does not undo your edits (they are in the BIN); it only drops that table's undo history. Opening a different BIN or XDF closes all the tabs.

Pins, tags and notes

  • Pin (the star button above the table) keeps a table in the Pinned folder at the top of the list, so the tables you use most are one click away. Pins belong to you, not to a project, and are remembered between sessions. A pin is matched by the table's name, so it shows up with any XDF that uses the same name. Different XDFs often name the same table differently (for example several versions of the main VE table), so pin it once under each name you meet. Click the button again to unpin.
  • Tag labels a table (Done, Needs Work, WOT, Review, Skip) and the list can be filtered by tag.
  • The note (under Notes and description) is for your own remarks on a table. In a project, notes are stored with the project. Export notes... (menu, Records) writes them all to a text file.

Compare

Compare with BIN... (menu, Checks) marks every table that differs from another BIN of the same size with a dot, and every changed cell in an open table with an orange frame and the old value in its tooltip. When tables differ, the table list switches to Changed tables only so you see them at once; untick the box to see every table again. Inside a project, every BIN of the project is compared with the project's base automatically. A BIN you open with "Just open it" from outside the project is not. Stop comparing turns it off.

Reference BINs. Open Reference BINs folder (menu, Files) opens a shared folder, next to your projects and the XDF library, for reference BINs, such as a file a friend sent or a read from another car. Put them there once. Every compare dialog (Compare with BIN, the workbench, the hex view and segment swap) opens in that folder when it holds any BINs. When you open a BIN, the Tuner also looks there for a file of the same size with the same GM part numbers (OS IDs) as the open one; if it finds one, Compare with: <file> appears under Checks and compares with a single click. The folder is yours to fill, so the file is not guaranteed to be a factory BIN: check its name. A file identical to the open BIN, or the open BIN itself, is not offered. Folders inside Reference BINs are searched too.

Which compare do I use? The comparison stays switched on while you work, so you can keep editing with the differences showing: that is the one to use to check "what have I changed from stock?". The Compare workbench is a separate page for "what did this other tune change?": it lists the differing tables and cells and can copy tables into your BIN, and it does not leave anything marked afterwards. To see the changed bytes themselves, use the Hex view.

Hex view

Hex view... (menu, Tools) shows the open BIN byte by byte: address, 16 bytes per row, and the text each byte stands for. It works on a BIN that has no XDF too: if no matching XDF is found the BIN still opens (with no tables), so you can look at its bytes, check its checksums and swap segments. Choosing an XDF later keeps any swaps you made. It shows your unsaved edits too. Click a byte (or use the arrow keys, Page Up/Down, Home and End) to see its value as one, two and four bytes (the GM byte order) and which XDF table covers it, which is the quickest way to check whether a table address is right.

  • Go jumps to an address in hex (8360, 0x8360 or $8360).
  • Find looks for hex bytes (FF 8A 00) or text in quotes ("12212156") and wraps round the ends. Enter finds the next one.
  • Open table shades the table that is open in the editor in blue and scrolls to it.
  • Compare with BIN... (inside the hex view) shades every byte that differs in red and lists each run of differing bytes, with the table it falls in. Click one to jump to it, or use Previous and Next. The other BIN must be the same size. If you are already comparing, that BIN is used.

Compare workbench

Compare workbench... (menu, Tools) answers "what did this other tune change?" Choose another BIN of the same size, such as the stock file or a tune someone sent you. The left list shows every XDF table whose values differ, with how many cells changed. Click a table to see each changed cell on the right, as the value in the open BIN and the value in the other one.

  • Below the list, the page says how many differing bytes are outside every table (program code, checksums, the OS id). They are not listed here; the hex view shows them.
  • Tick one or more tables and choose Copy selected tables into the open BIN. It asks first, then overwrites those tables in the open BIN, in memory. Nothing is saved until you use Save As, which corrects the checksums.
  • A flag keeps the other bits of its word, so copying one flag does not change its neighbours.
  • Undo last copy puts back exactly what the newest copy replaced, newest first, and leaves your other edits alone. The Tools menu keeps an Undo table copy button while there is something to undo.
  • Every copy is written to the change log.
  • Without an XDF there are no tables to list. Use the hex view to see the differing bytes.

Copying a table brings its values only. If the other tune changed an axis that is a separate table, it is listed as its own table; copy it too if the two belong together.

Saving, checksums and Send to Flash

Save As... writes your edited BIN to a new file (it never overwrites the BIN you opened). In a project it starts in edits and suggests the next version name. Before writing, it corrects the checksums and then checks the result with PCM Hammer's own validator. The status bar says whether the file is valid.

  • If the file is valid, Send to Flash appears. It switches to the Flash tab and puts the file's path on the clipboard for the Flash tab's file picker.
  • If it says the file is not valid, do not flash it.
  • Check checksums (menu, Checks) checks the BIN as it is now, including unsaved edits, without changing it.
  • Closing the window, or switching project, asks before throwing away unsaved edits.

Change log and notes export

Every edit, undo, redo, patch and segment swap is appended to a log: changes.log in a project, otherwise a .changes file beside the BIN. Each entry has the time, the table, what was done and how many cells changed; small edits list every cell's old and new value. Open change log (menu, Records) opens it in your text editor.

VE wizard

The wizard suggests corrections to the open table (for example the main VE table) from a Logger recording. Open the table, then menu, Tools, VE wizard....

  1. Press Newest Logger log (the project's logs folder, or the Logger's folder) or Open log....
  2. Check the columns it picked: engine speed, load (MAP), the measurement, and an optional second trim.
  3. Choose what the measurement is: an air/fuel ratio or lambda (divided by the target you enter), or a fuel trim percent (added to the second trim if chosen).
  4. Look at Leave out samples that cannot be trusted (below). The wizard fills it in from the log's own columns.
  5. Set Min samples per cell and Max change %, tick RPM runs along the table's columns if it does, and press Calculate.
  6. Review the list, then Apply to table. It is one edit you can undo.

Leave out samples that cannot be trusted. A sample is only useful if it says what this cell should hold. These rules drop the ones that do not, and after Calculate the summary says how many each one removed ("Left out: 412 engine cold, 51 fuel cut"). Pick (none) for a rule to switch it off.

  • Coolant at least - a cold engine runs warm-up enrichment, which is not the table's job. The limit is in the column's own units, so the wizard starts at 160 for a Fahrenheit column and 70 for Celsius.
  • Throttle moves under - while the throttle is moving fast, the fuel the sensor reports belongs to an earlier moment. The default is 50 % per second.
  • Fuel cut - choose an injector pulse or duty column. A reading near zero means the fuel was cut (deceleration), which reads lean by definition.
  • Steady for - engine speed and load must have stayed put for this many milliseconds before a sample counts. It is off to begin with; try 800. It leaves fewer samples, covering fewer cells, but the ones that remain are more honest.
  • Wideband delay - a wideband sensor reads the exhaust a moment after the burn (often about half a second). Each sample is paired with the reading that much later, so the correction goes to the cell that actually made it. It is off to begin with.

The throttle, steady and delay rules need the log's elapsed times. Logs from the Logger have them; if one does not, the page says so and the summary notes that those rules were skipped.

Each logged sample goes into the nearest cell using the table's own axes, and a cell's correction is the average over its samples. The table's axes must list real values (RPM and kPa), not just 1, 2, 3. These are suggestions: they only mean something for driving where that table actually controls the fuelling (for example speed-density, or MAF failure). Review them before you use them.

Log map

Log map... (Tools) shows where a logged drive actually went on the open table. Select a table with real axis values (the main VE table, for example), open a log written by the Logger (or use Newest Logger log), and check that the engine speed and load columns are the right ones. Each sample is placed in the cell the table's own axes put it in, the same way the VE wizard does it. Nothing in the BIN changes.

  • By default a cell shows how many samples landed there, and the shading gets stronger with more samples. Empty cells are the ones the engine never visited, so there is nothing to learn about them from this log.
  • Choose a channel under Show (fuel trim, air/fuel ratio, knock retard...) and a Figure (average, lowest or highest) to see that instead, shaded from blue (low) to red (high).
  • Point at a cell for its sample count, average, lowest and highest, and the table's own value. Show the table's own values too prints that value under each figure.
  • If the map looks sideways, tick or untick Engine speed runs along the table's columns.

Logging profiles

Menu, Tools, Logging profiles... lists ready-made lists of what to log (VE tuning, fuel trims, spark and knock, MAF check). They live in Documents\PcmSuite\Profiles, shared with the Logger, so a profile you save from the Logger appears here too. Use in Logger switches to the Logger tab and puts the file's path on the clipboard: press Connect, then Params, Open Profile, and paste it into the file name box.

Live trace

Live outlines, in blue, the cell the engine is in right now. It needs:

  • the Logger connected and logging (it stays connected when you switch to the Tuner),
  • engine speed and MAP being logged (the VE Tuning profile does),
  • a table with RPM on one axis and manifold pressure (kPa) on the other, with real axis values.

A line beside the table name shows the readings. If something is missing it says what. The trace only reads; it never changes the PCM or the BIN.

Patches and segment swap

  • Patches from the XDF (such as a speed limiter or a code that disables something) show a page with Apply patch and Take patch back.
  • Swap segments... (menu, Tools) copies whole calibration segments from another BIN into the open one. Some segments are marked risky because they can change the vehicle's identity or leave the BIN inconsistent. Undo segment swap puts the overwritten bytes back, one swap at a time, newest first: click it again to undo the one before.
  • Before anything is copied, the Tuner compares the operating system of the two BINs (its part number, not the calibration's). Same OS is shown in green. If they differ (red), or one cannot be identified (amber), copying asks for an explicit confirmation: a calibration written for one operating system can stop the PCM from starting in another. The system segment, which holds the VIN and security data, always asks too.

Drag and drop, command line

  • Drop a .bin on the Tuner to open it. If that would switch project, or add the file to the open project, you are asked first.
  • Drop an .xdf to use it (a readable one is added to the XDF library). Drop a project folder or its project.json to open that project.
  • PcmSuite.exe "file.bin" (or "Open with" from Explorer) opens that BIN in the Tuner; an .xdf argument loads that XDF.

When something goes wrong

  • "No XDF found" - the message lists the BIN's part numbers and the folders searched. Put an XDF with that number in its name in one of them, or use Open XDF.
  • "Cannot be read ... protected" - see Protected XDFs above; use an unprotected XDF.
  • Values look wrong, or a warning mentions a table that "is not in this XDF" - the XDF does not match this BIN, or an equation refers to a table the XDF lacks. Do not edit that table.
  • Live shows nothing - the Logger must be connected and logging, with engine speed and MAP in the profile.
  • Save As says the file is not valid - do not flash it. Run Check checksums and read the details; compare with the base to see what changed.
  • A dropped file does nothing - the status bar at the bottom says what it expected.
